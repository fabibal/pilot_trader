**Code and reliability audit — 2026-09-08**

The highest-risk defects were permanent signal loss after failed extraction,
replacement of damaged ledgers with empty history, and incorrect resolution of
expired calls. These have regression tests and fixes in this change. The
remaining performance statistics should still be treated as an incomplete
scorecard: the underlying position model loses earlier trading cycles and does
not distinguish short entries from long exits.

Reviewed the ingestion, extraction, reconciliation, resolver, X digest and
forecast pipelines, native YouTube analysis, Reddit miner, sentiment history,
dashboard callbacks and rendering, Docker configuration, model watchdog, backup
script, existing tests, and operational notes. Read runtime data and recent logs
without changing them. The active-account sample contains 265 signal records
and 105 position records; 10 summary ledgers contain 1,322 records. These are a
local snapshot, not guarantees about source completeness.

**Decisions and remaining risks, in priority order**

1. **High — archive trading cycles before relying on win rates.**
   `reconcile.reconcile` keys everything by account/portfolio/ticker. A new buy
   after a full close clears that same position's entry, stop, target, dates,
   and size. The event log remains intact, but the earlier completed cycle is
   absent from the resolver's input. The current active-account event log has
   six reopening events across five tickers. A correct fix needs a cycle ledger
   and stable cycle IDs, with agreed treatment of recaps, adds, partial exits,
   and backdated trade disclosures. This was not silently changed into a new
   statistical model.

2. **High — short entries are conflated with exits.**
   `monitor.EXTRACTION_SYSTEM` maps both a new short call and a long exit to
   `sell`; reconciliation only closes an already-open position and never opens
   a short. Chart-only bearish promotion similarly becomes a full exit.
   `resolver._is_long` then infers direction from target/stop geometry, while
   dashboard return formulas assume long exposure. Introduce explicit intent
   and direction before claiming symmetric long/short coverage.

3. **High — price-path evaluation still contains look-ahead and fill ambiguity.**
   Daily OHLC includes price action before an intraday tweet; recap trade dates
   may precede the public disclosure. Later stop/target updates are folded into
   one position and then applied retrospectively over its entire price path.
   No target/stop chronology or actual fill is modeled. Stop gaps fill at the
   stated stop, and a breakeven explicit close counts as a loss. Decide whether
   the product measures publicly executable calls or the analyst's claimed
   trades. Intraday prices and timestamped level changes may be necessary.
   Explicitly closed calls deliberately still use their entire holding window,
   while unresolved open calls expire after 30 days; harmonizing that policy is
   a separate decision.

4. **High — missing prices remain a selection bias.**
   Old calls can become `expired` when OHLC is missing entirely, and unpriceable
   closed calls are dropped from `influencer_resolutions`. No-data cases are not
   counted separately in the displayed denominator. Add an explicit unknown /
   unpriceable outcome and show coverage. The current caveats do not make this
   exclusion fully visible.

5. **High — authenticated production exposure is not verified.**
   The operational notes describe reverse-proxy Basic Auth, but the app itself
   has no authentication and binds on all host interfaces. The proposed Compose
   hardening does not restrict port 8051 or verify the reverse proxy/firewall.
   The app still uses Dash's development server. Confirm that every external
   route requires authentication, then deploy behind a production WSGI server
   with resource/request limits. Host networking remains as configured because
   changing it would affect the existing reverse-proxy routing.

6. **High — the repository backup script is not a runtime-data backup.**
   `scripts/auto_backup.sh` commits and pushes Git changes; primary JSON ledgers,
   state, and sentiment history are gitignored. External backups were not
   verified. Establish consistent versioned backups and a restore test before
   a storage migration. The automatic `git add -A` also means new sensitive
   files can be published if ignore rules or the host-local secret scanner miss
   them; it can publish unfinished work without review.

7. **Medium — ingestion windows still permit holes.**
   `fetch_getxapi`, `fetch_posts`, and `fetch_search` stop when a page contains
   an old/seen tweet. A pinned or out-of-order tweet can stop pagination early;
   a failed digest post below a newer already-seen page may not be revisited.
   `MAX_FETCH`, per-feed caps, and YouTube's roughly 15-entry RSS window bound
   catch-up. The trade retry fix protects failures already fetched by the new
   code, not unfetched posts or losses from historical runs. Durable raw-item
   queues plus pagination cursors and gap alarms would address this. Increasing
   fetch bounds alone changes cost and does not prove completeness.

8. **Medium — chart enrichment is optional and not durably retried.**
   A valid text signal is deliberately retained if its optional vision pass
   fails; losing a known exit because a thumbnail is unavailable is worse.
   Digest posts similarly retain text-only summaries. Missing chart fields or
   chart-only signals may therefore remain missing after the source is marked
   seen. A separate enrichment queue would fix this without rebilling text.
   The new trade pending queue can also grow if a text response fails forever;
   it has no dead-letter or operator-review mechanism yet.

9. **Medium — forecast clustering can merge distinct research calls.**
   Identity intentionally ignores timeframe and uses the first number of a
   range. Thus a point target and a range with that lower bound can collide,
   as can targets for different years or later revisions. Long nonprice target
   strings are truncated in the fallback identity. Preserve the existing
   noise-reduction policy until forecast identity/versioning is explicitly
   specified. This is not just a string-normalization bug.

10. **Medium — forecast reach can be overstated.**
    `_merge_sources` deduplicates only against the retained capped source list,
    while `source_count` is uncapped. Re-forcing a previously discarded source,
    or processing it again after seen-ID retention expires, can increment reach
    twice. The dashboard labels this count as reporting accounts even though
    it counts tweet IDs, and its legacy row-merger does not accumulate the
    complete source-ID union for subsequent overlaps. Decide whether reach
    means unique posts or unique accounts; retain stable identities separately
    from display samples.

11. **Medium — Reddit is still unavailable, not actually disabled.**
    Recent local logs continue to show HTTP 402 for all five subreddits. The
    code still attempts normal ingestion; there is no disabled-mode switch.
    The documented scheduler still includes the miner; the live crontab was
    not changed or independently verified. Options are funding the existing
    source, choosing and authorizing another source, or retiring the feature.
    No claim is made that Reddit's official API is currently free/available for
    this use. An explicit source-health record would let the dashboard separate
    an outage from a quiet strategy week.

12. **Medium — CURRENT VIEW is not an independent-source consensus.**
    Stale views still count in `_consensus_tally`; Cowen X and YouTube are
    separate rows for the same analyst; neutral promo posts can influence the
    synthesis. Sparse YouTube feeds extend to eight videos, potentially months
    of history. History's source/count/from-date/to-date key can also collapse
    different same-day windows into one point. These are weighting/identity
    decisions, not reasons to remove the intentional market-signal filter or
    Hungarian corruption safeguards.

13. **Medium — market-price adjustment and cache policy need a coordinated fix.**
    Dashboard historical fetches use yfinance defaults and compare resulting
    prices with literal tweet levels. The disk cache assumes past closes never
    change, but corporate actions, adjustments, corrections, and holiday
    fallback dates complicate that assumption. A stock's levels and its price
    series need the same adjustment basis. Cache versioning/invalidation must
    accompany any change; simply changing `auto_adjust` leaves existing cached
    values inconsistent. No live price fetch or cache rewrite was performed.

14. **Medium — cost observability remains incomplete.**
    X/YouTube costs are printed to logs rather than recorded in a common usage
    ledger. Failed runs can incur spend without final aggregate telemetry.
    GetXAPI retry attempts are not all included in reported call counts. Raw
    Gemini usage metadata is not persisted, so old tool-token omissions cannot
    be accurately backfilled. Record per-operation model, full usage, status,
    and the price schedule used before advertising a total system cost.

15. **Medium — durability is not transactional.**
    Sidecar locks prevent cooperating writers from racing, but do not protect
    against tools that ignore them. Files are still committed separately; a
    crash can leave trades/positions/state or summaries/view/history briefly
    inconsistent. Sentiment append failures remain log-only and may leave a
    missing point. File fsync does not provide a multi-file transaction or
    guarantee directory-entry durability after power loss. Consider SQLite
    transactions with backups once a schema/cycle migration is agreed.

**YouTube and Gemini compatibility findings**

The active text extractor and Reddit/forecast triage model are
`gemini-2.5-flash-lite`, not `gemini-3.1-flash-lite` from the task description.
The installed SDK is `google-genai==2.22.0`; its `Part` accepts
`media_processing=AGENTIC`, and its usage type explicitly defines total tokens
as prompt + tool-use input + candidates + thoughts. Recent local YouTube logs
show native-video successes after the migration. No live Gemini request was
made during this review, so these are SDK/log checks, not a fresh service test.

Google's current documentation supports agentic processing for Gemini 3.7 and
explains the separate navigation-thought and loaded-content token categories.
The pipeline retains the native-video path, explicit MIME type, and existing
model selection. [Google video documentation](https://ai.google.dev/gemini-api/docs/video-understanding).

There is an unresolved thinking-configuration discrepancy: current documentation
lists `low`, `medium`, and `high` for Gemini 3.7, while this installation's recent
logs show successful calls using `thinking_budget=0`. The docs currently show
Interactions API examples whereas the application uses `generate_content`.
Keep the known-working setting pending a controlled request that verifies the
exact model/endpoint behavior; do not infer that budget zero disables agentic
navigation tokens. All registered feeds still have deep thinking disabled.
[Google thinking documentation](https://ai.google.dev/gemini-api/docs/thinking).

The current standard Gemini 3.7 rate is $0.75/M input and $3.75/M output through
2026-12-31, rising to $1.50/M and $7.50/M on 2027-01-01. Existing constants lack
automatic date rollover. Add a dated price schedule before that boundary;
retain the rate actually used with each usage record.
[Google pricing](https://ai.google.dev/gemini-api/docs/pricing).

Google currently lists no shutdown date for `gemini-2.5-flash-lite`; the listed
shutdown for `gemini-3.1-flash-lite` is 2027-05-07. There is no reason to make the
previously suggested migration on the basis of the old cancelled date.
[Google deprecations](https://ai.google.dev/gemini-api/docs/deprecations).

The former transcript/Whisper/download code is absent from the active YouTube
path. A legacy Whisper badge remains only to display old records. `--force` on
an entirely unknown video still cannot infer publication metadata from its ID;
use a metadata fetch if this manual workflow must be complete. Agentic tool
navigation can produce usage above the nominal final-output cap, as existing
logs demonstrate; treat that cap as neither a strict total-token ceiling nor a
guaranteed dollar budget.

**Maintainability and dead paths**

The dashboard remains a large module with manually repeated feed/tab registries,
callback return tuples, and duplicated forecast normalization. This creates
registry drift risk but a wholesale UI rewrite would obscure the correctness
fixes. The new shared modules isolate storage, response validation/accounting,
and rolling-view recovery without importing Gemini into the dashboard.

Obsolete parsing helpers superseded by validation were removed. The fixed
Dockerfile no longer references deleted IBKR modules. The non-influencer reply
gate, portfolio schema compatibility fields, and `--batch` /
`--backfill-batch` compatibility flags remain intentionally. Unused legacy price
series/portfolio helpers and old provider comments still merit a separate
cleanup. Dash emits a local warning that builtin `dash_table.DataTable` will be
removed in a future major version; the direct dependency is pinned, and a grid
migration is deferred. Direct dependency pins are not a transitive lockfile or
a vulnerability audit.

**Validation and rollout limits**

- Baseline: 23 tests passed. After changes: **82 tests passed** with one existing
  Dash DataTable deprecation warning.
- Regression tests use synthetic data, temporary directories, mocked Gemini
  responses, and blocked external requests/notifications. They exercise the
  installed native-video SDK fields without spending API credits.
- Flask test client: `/`, `/_dash-layout`, and `/_dash-dependencies` return 200.
  This does not test the external proxy, authentication, browser layout, or
  real yfinance/Gemini/GetXAPI responses.
- Application modules parse; Docker COPY inputs exist; `docker compose config
  --quiet` and `git diff --check` pass.
- Docker daemon access was denied by the environment. No image build,
  container recreation/restart, or live deployment was performed. The running
  dashboard retains its previous configuration until recreated. Its source is
  bind-mounted; scheduled host Python jobs will read the changed source on
  their next execution.
- The hardened Compose mount prevents the dashboard from persisting its
  historical-price cache. Existing cache files remain readable; new prices
  remain cached in memory until process restart. Container CPU/RAM statistics
  show unavailable without the Docker socket. A dedicated writable cache
  volume can restore persistence without writable access to primary ledgers.
- No production ledger was rewritten, historical analysis rerun, credential
  changed, subscription funded, message sent, or change committed/pushed.
  Historical losses and inaccuracies are not repaired by prospective fixes.
